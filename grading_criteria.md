# IRMS Assignment Grading Criteria

---

## 📊 Total: 100% (+10% Bonus Seminar)

---

# 1. Task 1: Software Architecture Design (55%)

## 1.1 Context Description (5%)

- Thoroughly describe the context of the system (ITS/IRMS)
- Identify:
  - Functional requirements
  - Non-functional requirements
  - Objectives and scope

---

## 1.2 Architecture Style Selection (3%)

- Compare different architecture styles
- Justify the chosen architecture

---

## 1.3 Software Architecture Design (20%)

### 1.3.1 Module View (12%)

- Identify system modules
- Define responsibilities
- Show relationships/dependencies

### 1.3.2 Component-and-Connector View (5%)

- Show runtime components
- Describe communication:
  - APIs
  - Events
  - Data flow

### 1.3.3 Allocation View (3%)

- Map software to hardware
- Show deployment:
  - client devices
  - server
  - database

---

## 1.4 UML Class Diagram (7%)

- Define classes, attributes, methods
- Show relationships:
  - association
  - inheritance
  - composition

---

## 1.5 Apply SOLID Principles (15%)

### 1.5.1 Single Responsibility (3%)

- Each class has a single responsibility

### 1.5.2 Open/Closed (3%)

- Open for extension, closed for modification

### 1.5.3 Liskov Substitution (3%)

- Subclasses can replace base classes

### 1.5.4 Interface Segregation (3%)

- Avoid large, general interfaces

### 1.5.5 Dependency Inversion (3%)

- Depend on abstractions, not concrete classes

---

## 1.6 Future Extensibility (5%)

- Ability to extend system:
  - add features
  - scale modules
  - integrate new services

---

# 2. Task 2: Code Implementation (30%)

## 2.1 Implement Core Functionalities (15%)

### 2.1.1 Functionality correctness (15%)

- System runs correctly
- Core features implemented properly

### 2.1.2 Bonus: Multi-module implementation (+10%)

- Implement more than one main module

---

## 2.2 Apply SOLID Principles in Code (15%)

### 2.2.1 Single Responsibility (3%)

### 2.2.2 Open/Closed (3%)

### 2.2.3 Liskov Substitution (3%)

### 2.2.4 Interface Segregation (3%)

### 2.2.5 Dependency Inversion (3%)

---

# 3. Task 3: Documentation and Reporting (5%)

## 3.1 Reflection Report (3%)

- Describe:
  - challenges
  - lessons learned
  - how SOLID improved design

## 3.2 Division of Work (2%)

- Clearly assign responsibilities
- Show contribution of each member

---

# 4. Presentation / Demo (10%)

## 4.1 Demo (2%)

- System works during presentation

## 4.2 Presentation Skills (3%)

- Clear explanation
- Logical flow

## 4.3 Slides (3%)

- Well-structured
- Easy to understand

## 4.4 Q&A (2%)

- Ability to answer questions

---

# 5. Bonus: Seminar (+10%)

- Additional points for seminar participation
